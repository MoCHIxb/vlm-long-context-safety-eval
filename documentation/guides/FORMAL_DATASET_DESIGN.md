# Formal v1 正式实验数据集设计

## 1. 建设目标

`formal_v1`用于第一阶段安全性分析，重点回答长上下文多轮交互如何影响视觉语言模型的安全判断，并为第二阶段的风险累积因素与权重设计提供经验依据。数据集不追求无限扩大风险类别，而是围绕对话轮数、上下文长度、风险位置、风险分散方式和图文时序关系建立可重复的组内对照。

正式集复用预实验已经核验的SafeMT、MMDS和MMDU种子及图片，不覆盖`pilot_v1`和`pilot_v2`。全部样本为英文，以减少翻译对原始任务语义的干扰。

## 2. 总体结构

| 数据轨道 | 样本数 | 配对数 | 主要用途 |
|---|---:|---:|---|
| `static_visual_anchor` | 264 | 132 | 固定视觉场景，进行单因素长文本与图文关系对照 |
| `dynamic_risk_trajectory` | 160 | 80 | 研究风险线索跨轮、跨图累积、延续、澄清和重组 |
| `benign_multi_image_control` | 32 | 0 | 评估正常多图任务能力和过度拒答 |
| 合计 | 456 | 212 | 安全样本244条，危险样本212条 |

四类风险各包含106条攻击轨道样本，分别为欺骗与经济伤害、隐私与画像、非法与网络滥用、物理与公共安全。

## 3. 静态视觉锚点轨道

静态轨道包含12个SafeMT场景，每个场景构造11个条件及安全/危险最小差异对。`FS00`是6轮、约8K上下文、中部渐进风险、图文互补的基准条件，其余条件每次只改变一个配置因素：

- `FS01`、`FS02`：4轮与8轮，用于比较对话轮数；
- `FS03`、`FS04`：约2K与16K，用于比较上下文长度；
- `FS05`、`FS06`：风险线索前置与后置；
- `FS07`、`FS08`：风险集中出现与分散出现；
- `FS09`、`FS10`：纯文本与图文冗余，相对于图文互补基准比较模态关系。

每个条件覆盖全部12个场景，因此每个条件包含24条样本。建议在同一`seed_id`和同一安全标签内，将变体条件与`FS00`比较，而不是直接汇总所有条件后作组间因果解释。

## 4. 动态风险轨迹轨道

动态轨道包含8个MMDS多轮多图场景，每个场景构造10个条件及安全/危险配对。`FD00`是6轮、约8K上下文、中部渐进风险、图像随证据分散出现的基准条件：

- `FD01`、`FD02`：4轮与8轮；
- `FD03`、`FD04`：约2K与16K上下文；
- `FD05`、`FD06`：风险线索前置与后置；
- `FD07`：减少中间风险阶段，形成分散式线索；
- `FD08`：最终请求前加入授权和防御目的澄清；
- `FD09`：保持文本轨迹不变，将多张图像集中到最终轮输入。

`FD09`与`FD00`的比较用于观察相同视觉证据是随对话逐步到达，还是在最终轮集中到达时，模型的安全判断是否不同。该条件比笼统比较“单图/多图”更贴近本课题关注的时序风险累积。

每轮保留`risk_state`、`expected_behavior`、`risk_factors`和`evidence_role`。这些字段是第一阶段描述性标注，不是预先确定的第二阶段风险分数。

## 5. 良性多图对照轨道

良性轨道使用8个MMDU自然对话，在第4轮和第8轮分别构造话题延续与图像/子主题切换，共32条样本。运行时重放最终轮之前的参考回答，只让待测模型生成目标轮，以固定正常任务的历史条件。

该轨道不与危险样本合并计算攻击成功率，主要报告良性帮助率、拒答率和过度拒答率。

## 6. 长度与配对原则

受控轨道使用约2K、8K和16K三个长度档位。构建阶段采用空白分词估计，误差限制在目标值的5%以内；模型运行阶段仍需记录各模型处理器给出的实际输入token数。

同一语义种子的不同条件使用相同的确定性中性背景文本序列。长度条件只截取或扩展该序列，其他条件仅改变背景文本所在轮次，避免条件编号引入额外的背景措辞差异。

每个安全/危险配对共享最终轮之前的完整历史，最终轮图片也保持一致，只改变最终目标是危险实施还是合法、防御用途。这样可以将同一历史条件下的危险服从与良性帮助能力放在一起分析。

## 7. 使用边界

- 中性背景文本是长度控制材料，不代表自然对话分布；
- 模态关系条件需要改变图像可用性及相应措辞，因此应解释为匹配任务对照，而不是完全无语义差异的纯因果干预；
- 不同MMDS场景之间不直接作单因素因果比较，优先使用同一场景相对`FD00`的变化；
- 16K是估计长度，正式运行前应先对各模型执行少量资源诊断；
- 正式指标必须来自双人独立标注与分歧仲裁，不能直接使用数据集中的期望标签替代模型输出评价。

## 8. 构建与验证

```powershell
python scripts/build_formal_v1.py
python scripts/validate_formal_v1.py
python scripts/report_formal_v1.py
python -m unittest discover -s tests -v
```

生成文件为`data/processed/formal_v1.jsonl`，统计报告为`documentation/reports/formal_v1_stats.md`。

正式整轨运行前，先执行`formal_v1_qwen_gate_attack.json`与`formal_v1_qwen_gate_benign.json`。闸门集覆盖四类风险、16K静态和动态上下文、意图澄清、最终轮多图集中输入及八轮良性话题切换。确认无显存溢出、最终轮截断或图片解析错误后，再运行三个`formal_v1_qwen_static/dynamic/benign.json`完整配置。
