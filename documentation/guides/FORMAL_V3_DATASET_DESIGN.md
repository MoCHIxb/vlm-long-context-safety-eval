# `formal_v3` 核心受控数据集设计

## 1. 研究边界

`formal_v3`只定义输入数据、受控因素和配对关系。模型类型不属于数据集因素，也不参与样本构造。不同模型在数据冻结后运行同一测试面板，仅用于比较同一因素在不同模型上的表现是否一致。

第一阶段的数据因素为：视觉证据时序、上下文长度、对话轮数、风险位置、风险分布、图文关系、意图轨迹、风险类别及安全/危险最终目标。

## 2. 独立统计单位

独立单位是`seed_id`代表的语义场景，不是JSONL行。目标为80个危险种子和64个良性种子，共144个独立场景。条件、标签和视觉时序版本都是同一种子的重复测量。

危险种子在四个一级风险类别中各20个；每类预先冻结4个子类型，每个子类型5个种子。任何只替换姓名、地点、数字或表面措辞的样本不得计为新种子。

## 3. 静态/动态主因素

主因素字段为`visual_evidence_schedule`：

- `static_initial_bundle`：同一证据集的全部图片仅在第一轮同时出现，后续不加入新图片；
- `dynamic_incremental`：完全相同的图片各出现一次，并按预定轮次逐步加入；
- `final_bundle`仅作为机制诊断，不纳入静态/动态主效应。

同一`seed_id`和条件下，静态与动态版本必须共享图片文件、图片顺序、用户文本、最终请求、轮数、目标长度、固定助手历史和标签。唯一允许变化的是图片所在轮次。这样估计的是视觉证据进入历史的时序效应，而不是数据来源、题材或图片数量差异。

## 4. 安全/危险最小差异对

每个危险条件生成`safe`和`unsafe`两条轨迹。二者共享全部历史和图片，只允许最终意图消歧文本发生必要变化：危险版本要求实质性完成风险目标；安全版本明确转向合法、防御、合规或风险缓解目标。

安全版本不能只是把危险词替换成“安全”，必须具有真实、可完成且需要同一视觉证据的良性目标。

## 5. 条件矩阵

参考条件`C00`为6轮、8K、中间位置、渐进分布、图文互补、意图逐步升级。`C01`至`C11`每次只改变一个因素：4/8轮、2K/16K、风险早/晚、集中/拆分、图文冗余/冲突以及澄清或去风险转向。

危险层规模为：

```text
80 seeds × 12 profiles × 2 evidence schedules × 2 labels = 3,840
```

良性层只控制长度与视觉时序：

```text
64 seeds × 3 context lengths × 2 evidence schedules = 384
```

总计4,224条轨迹、144个独立语义种子。

## 6. 图像证据要求

每个危险种子应包含3至4个语义连贯的证据包。良性种子优先使用3至4个证据包；在排除跨种子图片复用后，为在不复制或拼接无关图片的前提下保留64个独立良性场景，7个良性种子使用2个证据包。证据包应分别承担环境、实体、状态变化或结果等作用，并能形成跨图联合判断。单张来源图片不得通过简单复制、裁剪或颜色变化伪造成多个独立证据。

已有MMDS、SafeMT和MMDU资源可以作为候选素材，但必须重新建立场景规范和配对文本。仅有单张图的SafeMT样本必须补足语义一致且许可明确的图片，才能进入静态/动态主面板。

## 7. 质量控制

冻结前必须满足：

1. 四类风险与子类型配额完整；
2. 静态/动态版本的唯一差异是图片轮次；
3. 安全/危险版本的唯一实质差异是最终目标；
4. 图片存在、哈希稳定、来源与许可可追溯；
5. 同一证据图片集合不能跨数据划分泄漏；
6. 文本和感知近重复检查通过；
7. 实际模板化token长度达到目标容差；
8. 两名审校者确认场景独立性、风险类别、最小差异配对及预期行为；
9. 数据划分以`seed_id`为单位；
10. 构建脚本可确定性复现并输出数据哈希。

## 8. 构建阶段

1. 建立种子规范和子类型配额表；
2. 制作8个危险、8个良性种子的校准原型；
3. 生成其静态/动态及安全/危险配对，验证构造器；
4. 扩展至80个危险和64个良性独立种子；
5. 完成双人审校、近重复检查和来源审计；
6. 生成并冻结`formal_v3.jsonl`。

模型运行、模型选择及性能结论均在数据冻结之后开始，不写入种子或构造逻辑。
